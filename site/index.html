03 / THE STOP SEQUENCE

Close the loop.

A stop request needs a result. Every step leaves a record.

  1. 01

    Detect

    Observe on-disk spawn metadata. Evaluate rate, growth, breadth, depth and configured budgets.

  2. 02

    Contain

    Write a fuse. A synchronous guard denies new dispatches, even when the daemon is down.

  3. 03

    Stop

    Request a background stop. The default ladder keeps destructive escalation opt-in.

  4. 04

    Verify

    Watch for new spawns. Record what continued; pause or kill only under your configured policy.

  5. 05

    Post-mortem

    One screen for the rule, tree, token estimates and timestamped actions. Export as Markdown.

05 / FIT THE FUSE

Small binary.
Short setup.

macOS + Linux. No root required.

Install the binary, register the synchronous guard, then run the daemon in a dedicated terminal.

01 / HOMEBREW
brew install anujjjjjj/tap/fanoutfuse
OR / GO 1.24+
go install github.com/anujjjjjj/fanoutfuse/cmd/fanoutfuse@latest
02 / REGISTER GUARD
fanoutfuse install
03 / WATCH IN A DEDICATED TERMINAL
fanoutfuse run

Check your setup with fanoutfuse doctor. Remove the guard with fanoutfuse uninstall.

06 / YOUR MACHINE IS THE BOUNDARY

No data leaves. No prompts kept.

Local only. No network calls, cloud account or telemetry. FanoutFuse reads metadata from local transcripts and stores incident metadata on your machine. It never stores prompt or response text.

Control runs over a local Unix socket. Stop the daemon and use fanoutfuse purge to remove its stored metadata.

07 / BEFORE YOU RUN IT

Operator notes.

Why keep my existing count cap?

A hard ceiling still helps. FanoutFuse adds rate and tree-shape detection, a stop sequence with verification, and an incident record. The two controls work together.

Does install start the daemon?

No. It registers the synchronous guard. Run fanoutfuse run separately to watch sessions and detect new trips. Use fanoutfuse doctor to check the setup.

Will it kill my main session?

The default ladder contains new spawns and requests a background stop. Pause and kill require an opt-in policy. A process-group kill can end the session and lose in-flight work.

What if spawning continues after Stop?

The verifier watches for further spawns and records them. An opted-in escalation policy can pause or signal the process group. A stop request alone is never treated as proof that the tree stopped.

Does it measure my subscription quota?

No. Token totals and API-equivalent cost estimates are metadata-based. They are not a live subscription quota reading. Quota-velocity rules are outside the current release.

Can I try it without a live session?

Yes. Run fanoutfuse replay fixtures/69332.yaml from the repository, then fanoutfuse pm. The replay uses synthetic fixture events and simulated stop actions.

Which platforms are supported?

macOS and Linux, on arm64 and amd64. Windows is outside the current release. Run doctor to check transcript discovery, synchronous hook health and tmux availability.

What happens to my transcript files?

Transcript directories are read-only. Installation backs up and updates the local hook settings. Uninstall removes the guard; purge removes FanoutFuse's own stored metadata after the daemon is stopped.
